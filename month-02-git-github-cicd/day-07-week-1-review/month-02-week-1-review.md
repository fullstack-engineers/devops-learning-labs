# Month 2 Week 1 Review — GitHub Workflow and CI Basics

## What I reviewed

This week I practiced:

- GitHub Pull Request workflow
- GitHub Issues
- Basic GitHub Actions workflow
- Bash script CI check
- Docker build CI check
- Dockerized static website CI

## Day 1 — Pull Request Workflow

I practiced:

- creating a feature branch
- pushing the branch to GitHub
- creating a pull request
- merging the pull request
- pulling latest main locally
- deleting local feature branch

Important lesson:

Pull requests help teams review changes before merging into main.

## Day 2 — GitHub Issues

I practiced using GitHub Issues to track tasks.

Important lesson:

Professional teams track bugs, tasks, improvements, and CI/CD work with issues.

## Day 3 — First GitHub Actions Workflow

I created:

.github/workflows/first-ci.yml

Important lesson:

GitHub Actions can run automated workflows when code is pushed.

## Day 4 — Bash Check CI

I created a workflow that checks and runs a Bash script.

Important command:

bash -n script.sh

Meaning:

Check Bash syntax without running the script.

## Day 5 — Docker Build CI

I created a workflow that builds a Docker image.

Important lesson:

CI should confirm Docker images build successfully before merging or deploying.

## Day 6 — Dockerized Static Website CI

I created a static website with:

- index.html
- style.css
- Dockerfile
- GitHub Actions workflow

Important lesson:

A CI pipeline can automatically verify that an app can be packaged with Docker.

## Main Week 1 Result

I now understand the basic professional GitHub + CI workflow:

1. Write code
2. Commit changes
3. Push to GitHub
4. GitHub Actions runs checks
5. Green check means the change passed CI
6. Pull request can be merged safely# Month 2 Week 1 Review — GitHub Workflow and CI Basics
